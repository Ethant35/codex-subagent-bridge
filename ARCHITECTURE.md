# Architecture

Author: Ethan

The native Codex parent calls an MCP stdio tool. `cli.ts` validates the versioned envelope with strict Zod schemas, then calls the same `delegate` function as the production CLI. Instructions remain an exact user message; metadata goes in a separate system message. CLI selectors must agree with the envelope. Empty instructions, unknown fields, malformed paths, unsupported provider/backend pairs, and invalid limits fail before execution.

`runner.ts` owns the lifecycle. It persists QUEUED, claims one of two SQLite scheduler slots, snapshots authorized files, persists RUNNING, calls the selected adapter, verifies a nonempty terminal result, checks tool failures and output format, and publishes allowed edits. Failure cannot become COMPLETED. Duplicate UUIDs are refused. The scheduler transaction serializes claims and dead-owner recovery across processes sharing CPB_HOME. Atomic JSON replacement and fsync preserve run metadata; JSONL records allowed and denied operations. A process that dies without finishing is marked FAILED by inspect/runs. PID reuse can conservatively delay stale recovery; no PID from a saved record is ever killed.

OpenRouter uses documented HTTPS chat completions. The loop exposes only read_file, write_file, and list_files. It accepts one fixed catalog model, rejects model changes, checks finish reasons and tool argument JSON, accumulates usage, reserves a conservative input/output budget, and refuses further execution after cost becomes unknown under a finite limit. Only idempotent catalog GETs have bounded retries. Inference POSTs and file writes are not automatically retried.

Claude SDK and CLI both receive a private capability for the bridge's file MCP server. Their native filesystem, shell, network, subagent, and extension tools are disabled. Claude's official runtime remains trusted software. The SDK runs inside a supervised Node process; the CLI runs directly through argument-array spawn. Both use structured real outputs and record usage/session metadata. CLI API mode and SDK use bare mode; CLI subscription mode preserves official login with restricted mode, isolated settings, disabled hooks, explicit MCP configuration, and disabled memory/attachment expansion. See PROVIDERS.md for auth policy limits.

The tool broker enforces exact per-operation path membership, canonical roots, no path traversal, symlink or hard-link source access, regular files only, 512,000-byte files, an 8 MB snapshot, a persistent tool-step count, and a wall-clock deadline. It never provides a shell or network operation. Files are copied, never linked, into a unique private workspace. Writable content is published only after successful provider completion and source-hash checks. This is capability enforcement in trusted code, not model instructions alone.

Cancellation uses a per-run marker polled every 50 ms, AbortSignal, and POSIX process-group TERM/KILL cleanup. Runtime covers queue waiting, snapshot preparation, provider calls, and final result checks. Synchronous filesystem operations cannot be preempted mid-system-call. Provider cancellation may not stop work already accepted on a remote service.

The design deliberately excludes arbitrary shell commands, arbitrary URL access, recursive directory capabilities, other providers, undocumented subscription authentication, and Codex binary patches. Supporting arbitrary executable child code would require an additional OS sandbox; private directory copies alone would not suffice.
