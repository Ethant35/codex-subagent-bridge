# Interface scope and CLI release qualification

Author: Ethan  
Review date: 2026-10-22  
Baseline: `v1.0.0` (`5f3a3eb`)

## Product surface

This repository ships a local Node.js CLI (`cpb`, built from `src/cli.ts`) and a local stdio MCP server. The TypeScript source inventory contains provider adapters, process supervision, file tools, task/schema handling, storage, and workspace publication. `package.json` has no React, web framework, browser UI, native app framework, UI build tooling, or application dev server. The interactive surface is terminal text and MCP tool/result schemas. The package targets Node.js `>=22.13.0`, macOS and Linux; Windows is unsupported for supervised Claude execution. The recorded verification host is macOS arm64, Node 22.13.1, npm 10.9.2. That one host does not establish a complete OS/Node compatibility matrix.

There is no dashboard, web form, native screen, or HTML accessibility surface to audit. Do not run browser/native UI tests or invent React components to satisfy conditional UI guidance. There is no native fuzz harness or existing fuzz target in this TypeScript CLI; fuzzing the whole CLI would mix filesystem, process, database, and network effects. Keep fuzz-harness work inapplicable unless a deterministic parser or protocol boundary is selected as a narrow target with I/O isolated.

CLI-relevant usability still matters: keep `--help`, quick-start steps, doctor output, and actionable errors concise; preserve machine-readable JSON; do not disclose credentials in diagnostics; use clear success/failure states and report recovery paths. These are text-interface/documentation checks, not a claim of WCAG conformance.

This gate is for a locally installed CLI, not a hosted service. Browser Core Web Vitals, CDN/TLS, CORS, feature flags, service dashboards, and page-level accessibility scans do not apply. Keep local operational evidence proportionate: clear JSON errors, bounded process behavior, private local state, provider-call outcome metadata, and an explicit restore procedure. Do not claim a SaaS monitoring/SLO gate that this package does not operate.

## Release conclusion

Existing evidence supports the recorded v1.0.0 core qualification on one macOS arm64 / Node 22.13.1 host, with OpenRouter live tests and local Claude setup/process checks. It does not support a full all-platform release claim, a tested update/rollback path, offline backup/restore readiness, complete third-party license review, or live Claude compatibility. Close the marked gates or state those limits plainly in release notes. Claude stays experimental and externally blocked until a maintainer has the official runtime/account and completes the controlled live qualification; no author currently has those credentials or CLI.
