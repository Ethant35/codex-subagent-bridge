# Security model

Author: Ethan

The parent and local account authorize the envelope. Child model output, tool arguments, and file content are untrusted. The bridge, Node runtime, dependencies, filesystem, and official Claude runtime are trusted. This is a tool capability boundary for a single trusted local user, not a container for hostile native code or a multi-user service.

The child can read only explicit readable paths and write only explicit writable paths through the broker. It cannot run shell commands, arbitrary processes, HTTP requests, or recursively enumerate a repository. The bridge copies only declared paths into a per-run mode-0700 workspace. Source symlinks and hard links are rejected. Files must be regular, bounded, and inside a canonical root. Configuration directories are not exposed. File operations are checked in code and logged as allowed or denied. Any failed tool marks the task failed even if the model later reports success.

Authorized source contents and task instructions are sent to the selected provider. This is intentional data disclosure. A provider-only network policy means there is no model-callable network tool; it is not an OS firewall for trusted runtime telemetry/authentication. OpenRouter requests use a fixed HTTPS origin and refuse redirects. Claude uses its official runtime's network controls; administrator settings and the runtime itself are outside the bridge's security boundary. Do not run this preview where malicious administrators, compromised runtimes, or untrusted local processes can replace filesystem parents during a check/write sequence.

No arbitrary child executable is supported. Consequently the broker itself enforces filesystem capabilities without a model-controlled native process needing an OS sandbox. Claude's built-in tools, hooks, memory expansion, auto connectors, and automatic extensions are disabled through documented runtime controls. Unexpected runtime tools fail initialization. This still requires live Claude validation; no claim of fully verified cross-provider containment is made.

Successful results publish authorized changed files after all source hashes are checked. Do not edit the same files concurrently from another program. Multi-file publication is not a filesystem-wide atomic transaction: an I/O failure or abrupt host termination during publication can leave some authorized files updated. The run will not be certified COMPLETED without a final record, and staged files remain available for inspection. Never treat this bridge as a transactional database for source files.

Run JSON and event JSONL are redacted for known environment secrets and common key patterns. File contents and tool arguments are not logged as events. Raw provider stderr is not returned. Private execution capabilities contain exact instructions while a run is active and are removed in normal finalization. Failed staging directories retain authorized file data for recovery; they are not sanitized traces. Keep CPB_HOME private and remove old runs according to your own retention policy. Unknown secrets embedded in user files or model prose cannot be reliably recognized by pattern matching. Do not commit CPB_HOME or provider credentials.

Cancellation terminates the supervised POSIX group, including descendants that ignore TERM, before returning. Trusted runtimes must not deliberately escape the process group with setsid. Windows does not have this guarantee and Claude execution is refused there. Remote providers may continue an accepted request after local cancellation. Concurrency is limited to two active runs per CPB_HOME; using separate stores creates separate limits. Store records do not authorize arbitrary PID killing.

Report vulnerabilities privately through the repository owner's GitHub contact options. Do not include live keys, private prompts, or unsanitized runtime logs in public issues. GitHub Actions is disabled for this repository by owner instruction.
